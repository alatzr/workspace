# T1 观测窗口
## 思路
题目要求在 $`n`$ 个观测记录中选择一个**非空连续子区间（窗口）**，同时满足两个约束条件：
1. **耗时总和上限**：窗口内的耗时总和 $`\sum a_i \le B`$。
2. **类别频率上限**：任意类别在窗口中出现的次数至多为 $`K`$。
在满足上述条件的前提下，我们需要求出：
- **最长窗口的长度**。
- **达到该最长长度的不同窗口数量**。
## 算法：单调性与双指针（滑动窗口）
由于所有观测的耗时 $`a_i \ge 1`$（正耗时），这意味着**随着窗口右端点 $`r`$ 的向右扩展，窗口的耗时总和必然单调递增**。因此，我们可以使用双指针（滑动窗口）算法：

- 右指针 $`r`$ 负责不断向右扩展，将新元素纳入窗口。
- 当窗口内出现**总耗时超限**（`sum_a > B`）或**某类别数量超限**（`viol > 0`）时，左指针 $`l`$ 向右收缩，直到窗口重新恢复合法。
- 在每一个合法的窗口区间 `[l, r]` 结束时，它都是以 $`r`$ 结尾的**最大合法窗口**，直接利用其长度更新全局答案即可。
## 时间复杂度：$`O(n)`$

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAXN = 2e5 + 10;
int c[MAXN]; // c[i] 记录第 i 次观测的类别编号
long long a[MAXN]; // a[i] 记录第 i 次观测的正耗时
int cnt[MAXN]; // cnt[i] 记录当前滑动窗口中，类别 i 出现的次数

int main() {
    int n, K;
    long long B;
    cin >> n >> K >> B;
    // 读入所有观测数据
    for (int i = 1; i <= n; ++i) {
        cin >> c[i] >> a[i];
    }
    int viol = 0;        // 记录当前窗口中，出现次数超过 K 的类别数量
    long long sum_a = 0; // 记录当前窗口的耗时总和
    int max_len = 0;     // 记录满足条件的最长窗口长度
    long long ways = 0;  // 记录达到最大长度的不同窗口数量

    // 遍历所有区间 [l, r]
    for (int l = 1, r = 1; r <= n; ++r) {
        // 右端点 r 向右扩展，累加耗时
        sum_a += a[r];
        // 如果加入当前元素后，该类别的数量刚好达到 K 的上限，说明再多一个就会违规
        if (cnt[c[r]] == K) viol++;
        // 对应类别数量加 1
        cnt[c[r]]++;
        // 当窗口不满足条件（总耗时超过 B，或者存在任何类别数量超过 K）时，收缩左端点 l
        while (l <= r && (sum_a > B || viol > 0)) {
            int c_l = c[l];
            sum_a -= a[l]; // 移出左端点，扣除耗时
            // 如果移出前该类别的数量刚好是 K + 1，说明移出后它不再违规
            if (cnt[c_l] == K + 1) {
                viol--;
            }
            // 对应类别数量减 1
            cnt[c_l]--;
            l++;
        }
        // 此时以 r 结尾的窗口 [l, r] 是满足所有限制条件的最大有效窗口
        int len = r - l + 1;
        if (sum_a <= B && viol == 0 && len > 0) {
            // 如果当前窗口长度严格大于历史最大长度，更新最大长度并将计数重置为 1
            if (len > max_len) {
                max_len = len;
                ways = 1;
            } 
            // 如果当前窗口长度等于历史最大长度，方案数累加 1
            else if (len == max_len) {
                ways++;
            }
        }
    }
    // 输出最终的最长长度及对应窗口数量
    cout << max_len << " " << ways << "\n";
    return 0;
}
```

# T2 双规格补给
## 题意:
有 $`n`$ 个补给类别，每个类别提供两种规格的物品（重量和价值分别为 $`w_{i,1}, v_{i,1}`$ 和 $`w_{i,2}, v_{i,2}`$）。每个类别**最多选择一种规格**，也可以不选。背包容量为 $`B`$。此外，你可以**至多使用一次压缩盒**，将某一个被选中的物品重量从 $`w`$ 减为 $`\max(1, w - D)`$，价值保持不变。求在总重量不超过 $`B`$ 的前提下，能够获得的最大总价值。
## 思路：
本题可以看作是分组背包问题的变体。每个类别相当于一个物品组，组内有三个选项：**不选**、**选规格 1**、**选规格 2**。难点在于“至多使用一次压缩盒”。由于压缩盒的使用状态只有两种（**已使用** 或 **未使用**），我们可以将状态在动态规划中进行升维：

定义动态规划状态 $`dp[i][j][k]`$ 表示：考虑前 $`i`$ 个类别，当前背包总重量为 $`j`$，且压缩盒使用状态为 $`k`$（$`k = 0`$ 表示未使用，$`k = 1`$ 表示已使用）时，所能获得的最大总价值。

对于每个类别 $`i`$，我们可以枚举它的选择：
1. **不选**：$`dp[i][j][k] = dp[i-1][j][k]`$
2. **选规格 1**：
    - 不对该规格使用压缩盒：若 $`j \ge w_{i,1}`$，$`dp[i][j][0] = \max(dp[i][j][0], dp[i-1][j - w_{i,1}][0] + v_{i,1})`$
    - 对该规格使用压缩盒：若 $`j \ge \max(1, w_{i,1} - D)`$，$`dp[i][j][1] = \max(dp[i][j][1], dp[i-1][j - \max(1, w_{i,1} - D)][0] + v_{i,1})`$
3. **选规格 2**：
    - 不对该规格使用压缩盒：若 $`j \ge w_{i,2}`$，$`dp[i][j][0] = \max(dp[i][j][0], dp[i-1][j - w_{i,2}][0] + v_{i,2})`$
    - 对该规格使用压缩盒：若 $`j \ge \max(1, w_{i,2} - D)`$，$`dp[i][j][1] = \max(dp[i][j][1], dp[i-1][j - \max(1, w_{i,2} - D)][0] + v_{i,2})`$

由于当前状态只依赖于上一层状态，并且为了防止在同一类别中多次使用压缩盒，我们在更新背包容量时需要**逆序枚举**重量，同时对压缩盒状态 $`k`$ **从 1 到 0 倒序转移**。
## 算法：
1. 使用动态规划，状态数组大小为 `dp[B + 1][2]`（第一维为背包容量，第二维表示压缩盒是否已使用）。
2. 初始化 `dp` 数组为负无穷（表示不可达），`dp[0][0] = 0`。
3. 外层循环遍历每一个类别 $`i`$ ($`1 \le i \le n`$)。
4. 内层循环采用类似 01 背包的逆序方式遍历背包容量 $`j`$ 从 $`B`$ 到 $`0`$，同时逆序枚举压缩盒状态 $`k`$ 从 1 到 0。
5. 在每次转移时，尝试用当前类别的规格更新 `dp[j][k]`。
6. 最终答案为 $`\max_{0 \le j \le B, 0 \le k \le 1} dp[j][k]`$。
## 时间复杂度：
- 外层循环迭代 $`n`$ 个类别。
- 内层循环遍历背包容量 $`B`$（最大 6000），以及压缩盒状态（2 种）。
- 每个状态的转移是常数级的。
- 总时间复杂度为 $`\mathcal{O}(n \times B)`$。在 $`n \le 250, B \le 6000`$ 的数据规模下，总计算量约为 $`1.5 \times 10^6`$ 次基本运算，可在远低于 2 秒的时间限制内轻松通过。
- 空间复杂度为 $`\mathcal{O}(B)`$（通过滚动数组优化），满足 256 MiB 的限制。
## 参考代码：

```cpp
#include <bits/stdc++.h>

using namespace std;

// 题目数据范围
const int MAXB = 6005;
const long long INF = 0x3f3f3f3f3f3f3f3f;

// dp[j][k] 表示背包容量为 j，压缩盒状态为 k（0表示未使用，1表示已使用）时的最大价值
long long dp[MAXB][2];

int main() {
    int n;
    long long B, D;
    cin >> n >> B >> D;
    // 初始化 dp 数组为负无穷，表示状态非法
    for (int j = 0; j <= B; ++j) {
        dp[j][0] = -INF;
        dp[j][1] = -INF;
    }
    dp[0][0] = 0; // 容量为0、未使用压缩盒的初始价值为0
    for (int i = 1; i <= n; ++i) {
        long long w1, v1, w2, v2;
        cin >> w1 >> v1 >> w2 >> v2;
        // 预处理当前类别两种规格在压缩后的重量
        long long cw1 = max(1LL, w1 - D);
        long long cw2 = max(1LL, w2 - D);
        // 逆序遍历背包容量，防止同一类别被重复选择
        for (int j = B; j >= 0; --j) {
            // 倒序枚举压缩盒状态：先处理 k = 1，避免用当前状态更新出的 k = 1 反过来影响其他转移
            for (int k = 1; k >= 0; --k) {
                // 如果当前状态本身不可达，则跳过
                if (dp[j][k] == -INF) continue;

                // 选项 1：选择规格 1
                // 1.1 不使用压缩盒
                if (!k && j + w1 <= B) {
                    dp[j + w1][0] = max(dp[j + w1][0], dp[j][0] + v1);
                }
                // 1.2 使用压缩盒（之前未使用，当前使用）
                if (!k && j + cw1 <= B) {
                    dp[j + cw1][1] = max(dp[j + cw1][1], dp[j][0] + v1);
                }
                // 选项 2：选择规格 2
                // 2.1 不使用压缩盒
                if (!k && j + w2 <= B) {
                    dp[j + w2][0] = max(dp[j + w2][0], dp[j][0] + v2);
                }
                // 2.2 使用压缩盒（之前未使用，当前使用）
                if (!k && j + cw2 <= B) {
                    dp[j + cw2][1] = max(dp[j + cw2][1], dp[j][0] + v2);
                }
            }
        }
    }

    // 统计所有合法状态中的最大价值
    long long ans = 0;
    for (int j = 0; j <= B; ++j) {
        ans = max(ans, dp[j][0]);
        ans = max(ans, dp[j][1]);
    }
    cout << ans << "\n";
    return 0;
}
```

# T3 错峰亮灯日

## 题意：
给出两个二进制串 $`a`$ 和 $`b`$，长度分别为 $`n`$ 和 $`m`$，分别代表两座灯塔的工作日程。从第 $`0`$ 天开始，第 $`t`$ 天灯塔 $`a`$ 的状态为 $`a_{t \bmod n}`$，灯塔 $`b`$ 的状态为 $`b_{t \bmod m}`$（字符 `'1'` 表示亮着，`'0'` 表示熄灭）。“可观测日”定义为：在这一天中，**恰好有一座灯塔亮着**（即两座灯塔状态不同，一亮一灭）。求第 $`K`$ 个可观测日的天数编号（从 $`0`$ 开始编号）；如果永远没有可观测日，则输出 `-1`。

## 思路：
由于日程是周期性的，第 $`t`$ 天的状态取决于 $`(t \bmod n)`$ 和 $`(t \bmod m)`$。根据中国剩余定理和周期理论，两座灯塔状态的组合会在 $`L = \text{lcm}(n, m)`$ 天后形成一个循环。

由于 $`n, m \le 2000`$，它们的最小公倍数 $`L \le 2000 \times 2000 = 4 \times 10^6`$，这是一个非常小的范围。
我们可以通过以下步骤高效求解：

1. **预处理一个周期内的可观测日**：
    计算 $`L = \text{lcm}(n, m)`$。我们遍历从第 $`0`$ 天到第 $`L-1`$ 天的每一天，检查是否为可观测日（即 $`a_{t \bmod n} \neq b_{t \bmod m}`$）。如果是，将其记录在一个动态数组中。
2. **判断是否存在可观测日**：
    如果一个周期 $`L`$ 内的可观测日总数（设为 $`cnt`$）为 $`0`$，说明永远没有可观测日，直接输出 `-1`。
3. **利用周期性计算第 $`K`$ 个可观测日**：
    设 $`K`$ 是从 $`1`$ 开始计数的（第 $`K`$ 个），其在周期中的索引为 `target_idx = (K - 1) % cnt`（转换为从 0 开始），它所经历的完整周期数为 `full_cycles = (K - 1) / cnt`。
    则第 $`K`$ 个可观测日的天数编号为：

```math
\text{ans} = \text{full\_cycles} \times L + \text{days}[target\_idx]
```

## 算法：
1. 计算 $`n`$ 和 $`m`$ 的最大公约数 $`\text{gcd}(n, m)`$，进而得到最小公倍数 $`L = \frac{n \times m}{\text{gcd}(n, m)}`$。
2. 开一个静态数组（大小足够容纳 $`L`$）存储一个周期内所有可观测日的天数偏移量。
3. 循环 $`t`$ 从 $`0`$ 到 $`L-1`$，判断 $`a_{t \bmod n} \neq b_{t \bmod m}`$，若满足则存入数组。
4. 若统计出的周期内可观测日总数 $`cnt = 0`$，输出 `-1`。
5. 否则计算商与余数，直接算出第 $`K`$ 个可观测日的绝对天数编号并输出。

## 时间复杂度：
- 求 $`\text{gcd}`$ 及最小公倍数 $`L`$ 的时间复杂度为 $`\mathcal{O}(\log(\min(n, m)))`$。
- 预处理一个周期需要遍历 $`L`$ 天，$`L \le 4 \times 10^6`$，单次判断为 $`\mathcal{O}(1)`$，总耗时约十几毫秒，远低于 2 秒的时限。
- 查询计算为 $`\mathcal{O}(1)`$。
- 总时间复杂度为 $`\mathcal{O}(n + m + \text{lcm}(n, m))`$。
- 空间复杂度为 $`\mathcal{O}(\text{lcm}(n, m))`$，用于存储周期内的可观测日偏移量，在 512 MiB 内存限制下完全安全。
## 参考代码：

```cpp
#include <bits/stdc++.h>
using namespace std;
// 最大 lcm(2000, 2000) = 4,000,000
const int MAXL = 4000005;
// 存储一个周期内所有可观测日的天数偏移量
long long days[MAXL];

long long gcd(long long a, long long b) {
    return b == 0 ? a : gcd(b, a % b);
}

int main() {
    long long n, m, K;
    cin >> n >> m >> K;
    string a, b;
    cin >> a >> b;
    // 计算最小公倍数 L = lcm(n, m)
    long long g = gcd(n, m);
    long long L = (n / g) * m;

    long long cnt = 0;
    // 预处理一个周期 [0, L-1] 内的所有可观测日
    for (long long t = 0; t < L; ++t) {
        if (a[t % n] != b[t % m]) {
            days[cnt++] = t;
        }
    }
    // 如果一个周期内都没有可观测日，说明永远没有
    if (cnt == 0) {
        cout << -1 << "\n";
        return 0;
    }
    // 计算第 K 个可观测日对应的完整周期数和周期内索引
    // K 从 1 开始，转换为从 0 开始计数：K - 1
    long long full_cycles = (K - 1) / cnt;
    long long idx = (K - 1) % cnt;
    // 计算最终的绝对天数编号
    long long ans = full_cycles * L + days[idx];
    cout << ans << "\n";
    return 0;
}
```

# T4 双钥匙窗口
## 题意：
给定一个由小写字母和 `#` 构成的日志串 $`s`$，以及两个只含小写字母的钥匙串 $`p`$ 和 $`q`$。需要在 $`s`$ 中选择一个 $`p`$ 的完整出现和一个 $`q`$ 的完整出现，要求：
1. 两次出现**不能重叠**。
2. $`p`$ 的结束位置与 $`q`$ 的开始位置之间隔着的字符数必须在 $`0`$ 到 $`G`$ 之间。
3. 这些间隔字符中**不能包含 `#`**。
4. 出现的位置不同即视为不同的选择（$`p`$ 和 $`q`$ 可以相同）。
求满足条件的所有合法选择对数。
## 思路：
使用KMP字符串匹配算法或者字符串哈希来解此题，下面介绍字符串哈希做法，KMP算法可以观看此视频自学：
> https://meeting.tencent.com/crm/NbaLzE9Pbc

直接双重循环暴力匹配两者的所有出现位置会导致超时，因此可以采用 **字符串哈希 + 前缀和 + 双指针** 的高效组合：
1. **字符串哈希（Polynomial String Hashing）**：
    预处理主串 $`s`$ 的前缀哈希数组和进制幂次数组。通过定义好的 `get(l, r)` 函数，可以在 $`O(1)`$ 时间内获取主串任意子串的哈希值，从而通过与模式串的哈希值比对，快速找出 $`p`$ 和 $`q`$ 在主串中的所有匹配起点集合 `p_pos` 和 `q_pos`。
2. **前缀和快速区间判定**：
    为了判断 $`p`$ 和 $`q`$ 之间是否存在禁止出现的特殊字符 `'#'`，可以预处理一个字符 `'#'` 的前缀和数组 `cnt`。这样在任意区间内查询 `'#'` 的个数只需 $`O(1)`$ 时间，省去逐个扫描的开销。
3. **双指针维护距离与位置窗口**：
    以每个 $`q`$ 的出现起点 $`q\_start`$ 作为主控视角，利用双指针动态维护一个合法的 $`p`$ 起点索引区间 $`[p\_left, p\_right - 1]`$。该区间能同时满足：
    - $`p`$ 在 $`q`$ 的左侧且不重叠：$`p\_start + \text{len}_p \le q\_start`$。
    - $`p`$ 与 $`q`$ 的起点距离在限定阈值 $`G`$ 以内：$`p\_start + \text{len}_p \ge q\_start - G`$。
        在限定的区间内逐一检验夹断区间是否含有 `'#'` 并累计方案数。
## 算法：
1. **初始化与预处理阶段**：
    - 读入限制距离 $`G`$、主串 $`s`$ 及两个模式串。
    - 将主串转为 1-based 下标，预处理字符串的滚动哈希前缀和数组 `h` 与进制幂次数组 `p`。
    - 预处理特殊字符 `'#'` 的前缀和数组 `cnt`。
2. **模式串匹配定位**：
    - 遍历主串，利用 $`O(1)`$ 哈希比对分别找出匹配模式串 $`p`$ 和 $`q`$ 的所有起点集合 `p_pos` 和 `q_pos`。
3. **双指针高效计数**：
    - 外层遍历每一个 $`q`$ 的起点 $`q\_start`$，利用双指针调整并锁定满足距离限制的 $`p`$ 起点范围。
    - 对落在该范围内的每个 $`p`$ 起点，通过前缀和 $`O(1)`$ 检查其与当前 $`q`$ 之间的空隙是否含 `'#'`，无误则计入最终答案。
## 时间复杂度：
- **预处理阶段**：
    - 处理主串前缀哈希、幂次以及 `'#'` 的前缀和数组时间复杂度均为 $`O(n)`$。
    - 通过哈希扫描找出所有 $`p`$ 和 $`q`$ 的匹配起点，最坏情况下需要遍历主串，时间复杂度为 $`O(n + m_p + m_q)`$（其中 $`n`$ 为主串长度，$`m_p, m_q`$ 分别为两模式串长度）。
- **查询与统计阶段**：
    - 双指针在有序的起点数组上单调滑动，每个 $`p`$ 和 $`q`$ 的索引至多被进退访问一次，双指针扫描复杂度为 $`O(p_{\text{size}} + q_{\text{size}})`$。
    - 内部区间判断及哈希 `get` 均为 $`O(1)`$。
- **总时间复杂度**：$`O(n + p_{\text{size}} + q_{\text{size}})`$，能够完美通过 $`2 \times 10^5`$ 级别的数据规模。
## 参考代码
```cpp
#include <bits/stdc++.h>
using namespace std;
typedef unsigned long long ull;
typedef long long ll;
using namespace std;

// 定义常量：N 为字符串最大长度，P 为字符串哈希的进制
const int N = 200005, P = 131;
// h 数组存储字符串的前缀哈希值，p 数组存储进制 P 的幂次（p[0] 初始化为 1）
ull h[N], p[N] = {1};
// 核心函数：利用前缀哈希在 O(1) 时间内获取子串 s[l...r] 的哈希值
ull get(int l, int r) {
    return h[r] - h[l - 1] * p[r - l + 1];
}

int main() {
    ll G;
    cin >> G;
    string s, str_p, str_q;
    cin >> s >> str_p >> str_q;
    int n = s.length();
    int len_p = str_p.length();
    int len_q = str_q.length();
    s = " " + s;
    // 1. 预处理文本串 s 的前缀哈希值以及 P 的幂次
    for (int i = 1; i <= n; i++) {
        h[i] = h[i - 1] * P + s[i];
        p[i] = p[i - 1] * P;
    }
    // 2. 计算模式串 p 和 q 的哈希值
    unsigned long long hash_p = 0, hash_q = 0;
    for (char ch : str_p) hash_p = hash_p * P + ch;
    for (char ch : str_q) hash_q = hash_q * P + ch;
    // 3. 预处理 '#' 的前缀和数组，用于 O(1) 区间内快速判断中间是否存在 '#'
    vector<int> cnt(n + 1, 0);
    for (int i = 1; i <= n; ++i) {
        cnt[i] = cnt[i - 1] + (s[i] == '#' ? 1 : 0);
    }
    // 4. 遍历文本串 s，通过哈希比对找出所有匹配 p 和 q 的起点位置
    vector<int> p_pos, q_pos;
    if (len_p <= n) {
        for (int i = 1; i <= n - len_p + 1; ++i) {
            if (get(i, i + len_p - 1) == hash_p) {
                p_pos.push_back(i); // 记录 p 的 1-based 起点
            }
        }
    }
    if (len_q <= n) {
        for (int i = 1; i <= n - len_q + 1; ++i) {
            if (get(i, i + len_q - 1) == hash_q) {
                q_pos.push_back(i); // 记录 q 的 1-based 起点
            }
        }
    }
    // 5. 利用双指针统计满足所有限制条件的合法 (p, q) 对数
    long long ans = 0;
    int p_left = 0, p_right = 0;
    int p_size = p_pos.size();
    for (int q_start : q_pos) {
        // 移动左指针：排除距离 q_start 太远的 p（保证 p 和 q 的起点距离满足题目要求 G）
        while (p_left < p_size && p_pos[p_left] + len_p < q_start - G) {
            p_left++;
        }
        // 移动右指针：排除与 q_start 重叠或位于 q_start 之后的 p
        while (p_right < p_size && p_pos[p_right] + len_p <= q_start) {
            p_right++;
        }
        // 在当前合法的 p 起点区间 [p_left, p_right - 1] 内进行逐一检查
        for (int i = p_left; i < p_right; ++i) {
            int p_start = p_pos[i];
            int st = p_start + len_p; // p 结束位置的下一个字符（1-based）
            int ed = q_start - 1;       // q 开始位置的前一个字符（1-based）
            // 检查 p 和 q 之间的间隔区间是否包含 '#'
            if (st > ed || (cnt[ed] - cnt[st - 1] == 0)) {
                ans++; // 如果没有 '#' 且区间合法，方案数加 1
            }
        }
    }
    // 输出最终答案
    cout << ans << "\n";
    return 0;
}
```

## 题意
- 给定 $`n`$ 个设备和它们之间的直接转移费用矩阵 $`c_{i,j}`$（-1 表示无法直达）。
- 给定 $`m`$ 条先后偏序约束（表示设备 $`u`$ 必须在设备 $`v`$ 之前巡检）。
- 要求访问完所有 $`n`$ 个设备恰好一次（起点和终点均任意），使用的边必须是费用矩阵中的直接边。
- 求满足所有偏序约束的**最小总费用**以及取得该最小费用的**不同巡检方案数**（对 998244353 取模）。无解时输出 `-1 0`。数据范围：$`1 \le n \le 18`$。

### 第一步：拆解题意，建立直观模型（“这道题到底在让我们做什么？”）

引导学生把题目翻译成熟悉的图论/组合模型：
1. **画路径**：有 $`n`$ 个点，要找一条**经过所有点且仅经过一次**的路径（这就是经典的**哈密顿路径**）。
2. **看限制（先后顺序）**：如果要求 $`u`$ 必须在 $`v`$ 之前巡检，意味着在我们的走法中，$`u`$ 出现的顺序必须排在 $`v`$ 的前面。
3. **两个目标**：不仅要找**最小总路径权值**，还要统计**达到这个最小值的不同路径方案数**（结果取模）。
> 面对题目，先别急着写代码。我们看看 $`N`$ 的范围——$`N \le 18`$！在 OI 中，看到 $`N \le 18 \sim 20`$ 的图上遍历问题，你的第一反应应该是什么？对，大概率是**状态压缩 DP**！”

### 第二步：从暴力搜索（DFS）瓶颈引出状态设计

先让学生想想暴力的做法：
- 用 DFS 搜索全排列，每一步选下一个没走过的节点 $`v`$。
- 复杂度是 $`O(n!)`$，$`n=18`$ 时 $`18! \approx 6.4 \times 10^{15}`$，显然超时。

**引导思考（消除冗余）**：
- 假设我们已经走过了 $`\{1, 2, 3\}`$ 这三个设备，现在停在设备 $`3`$ 上。
- 我们是怎么到达 $`3`$ 的（是 $`1 \to 2 \to 3`$ 还是 $`2 \to 1 \to 3`$），会影响我们**接下来去访问 $`\{4, 5, 6\}`$ 的决策**吗？
- **不会！** 只要已访问的集合是 $`\{1, 2, 3\}`$，且当前位置在 $`3`$，后续的最小开销是完全一样的（具有无后效性）。

**由此引出 DP 状态**：

1. 我们用一个二进制二进制掩码 `mask`（$`0 \sim 2^n - 1`$）记录**哪些设备已经被访问过**。
2. 用 `u` 记录**当前停留在哪个设备**。
3. 定义：
    - $`\text{dp}[\text{mask}][u]`$：访问完 `mask` 中的设备，且最后停在 $`u`$ 的**最小费用**。
    - $`\text{cnt}[\text{mask}][u]`$：达到这个最小费用的**方案数**。
### 第三步：解决最大难点 —— 如何优雅地处理“先后顺序”？

学生最容易卡住的地方是：“先后顺序 $`u \to v`$ 该怎么在状压 DP 中高效判断？”

**直白解释**：
“要求 $`u`$ 在 $`v`$ 之前被巡检”，翻译成状压 DP 的语言就是：**在把 $`v`$ 加入集合之前，$`u`$ 必须已经在当前的 `mask` 里了！**

**位运算技巧（预处理）**：

- 设 `req[v]` 为一个二进制掩码，其中第 $`u`$ 位为 $`1`$，表示访问 $`v`$ 前**必须**先访问 $`u`$。
- 当我们试图从当前状态 `mask`（结尾为 $`u`$）扩展到新设备 $`v`$ 时，只需要检查：
    `(mask & req[v]) == req[v]`
- 如果这个条件成立，说明 $`v`$ 的所有前置依赖设备都已经被巡检过了，合法！
> **教学小技巧**：在黑板上画一个二进制掩码的按位与计算示例，比如 `mask = 1011`（点了 0, 1, 3），`req[v] = 0011`（依赖 0, 1），`1011 & 0011 == 0011`，学生一目了然。

### 第四步：状态转移与方案数更新（手把手写出逻辑）

明确了状态与限制后，带领学生写出转移逻辑：
设当前状态为 $`(\text{mask}, u)`$，我们想尝试走到下一个节点 $`v`$：
1. **合法性判断**：
    - $`v`$ 还未在 `mask` 中（`(mask & (1 << v)) == 0`）。
    - $`u \to v`$ 有直接边（`cost[u][v] != -1`）。
    - $`v`$ 的前置约束已满足（`(mask & req[v]) == req[v]`）。
2. **转移计算**：
    新状态 `next_mask = mask | (1 << v)`，新开销 `next_cost = dp[mask][u] + cost[u][v]`。
    
3. **双重更新（最小值与方案数）**：
    
    - 若 `next_cost < dp[next_mask][v]`（发现了更优解）：
        - 更新最小开销：`dp[next_mask][v] = next_cost`
        - 覆盖方案数：`cnt[next_mask][v] = cnt[mask][u]`
    - 若 `next_cost == dp[next_mask][v]`（发现了开销相同的另一种走法）：
        - 累加方案数：`cnt[next_mask][v] = (cnt[next_mask][v] + cnt[mask][u]) % MOD`

### 总结
在讲完之后，用三句话帮学生提炼本质：
1. **状态识别**：看到 $`N \le 18`$ 的无序遍历路径问题，首选**状压 DP**，用 `mask` 压缩已访问点集。
2. **约束转化**：将“先后顺序”转化成**按位与运算预处理（`req[v]`）**，实现 $`O(1)`$ 的秒级合法性校验。
3. **计数叠加**：求解方案数时，**更小则覆盖，相等则累加**。

## 流程思路

这道题是一道非常经典的**旅行商问题（TSP）变体**，融入了拓扑序约束（DAG 约束）以及方案数计数的要求。面对这类题目，我们要逐步将其拆解为标准的算法模型。
### 1. 题目关键信息与建模拆解
我们可以从以下几个维度来剖析题目：
1. **核心模型**：
* 巡检所有 $`n`$ 个设备，每个设备恰好一次，且必须走相邻设备之间的直接边。
* 这实际上是在寻找图上的**哈密顿路径（Hamiltonian Path）**，并在此基础上求**最短长度**与**最优方案数**。

2. **约束条件（先后顺序）**：
* $`m`$ 条先后约束 $`(u, v)`$ 要求 $`u`$ 在 $`v`$ 之前被访问。
* **注意**：这并不要求 $`u`$ 与 $`v`$ 紧挨着，只要在最终的访问序列中 $`u`$ 位于 $`v`$ 的左侧即可。
* 若约束存在环（如样例 3 中的 $`1 \to 2`$ 和 $`2 \to 1`$），则显然无解。

3. **数据范围**：
* $`n \le 18`$：这是极为关键的信号！在竞赛中，$`n \le 18 \sim 20`$ 的哈密顿路径/巡检问题，标准解法几乎一定是**状压动态规划（Bitmask DP）**。

---

### 2. 状态设计与转移方程

#### 状态表示

为了在 DP 的过程中实时检查先后约束是否满足，我们可以利用二进制掩码（Bitmask）表示已访问设备的集合：
* 设 $`S`$ 表示当前**已经巡检过的设备集合**（用二进制掩码 $`0 \sim 2^n - 1`$ 表示）。
* 设 $`u`$ 表示当前**最后巡检的设备**（$`u \in S`$）。
由于我们不仅需要求解**最小总费用**，还需要计算**达到该费用的方案数**，我们需要同时维护两个 DP 数组：
1. $`\text{dp}[S][u]`$：访问完集合 $`S`$ 中的设备，且最后一个设备是 $`u`$ 时的**最小费用**。
2. $`\text{cnt}[S][u]`$：达到 $`\text{dp}[S][u]`$ 这个最小费用的**巡检顺序数**（结果对 $`998244353`$ 取模）。
#### 先后约束的预处理

对于每个结点 $`v`$，如果存在约束 $`(u, v)`$，意味着在访问 $`v`$ 之前，**$`u`$ 必须已经被访问过**。
我们可以为每个结点 $`v`$ 预处理一个掩码 $`\text{req}[v]`$：
* $`\text{req}[v]`$ 的第 $`u`$ 个二进制位为 $`1`$，当且仅当存在约束 $`u \to v`$（即 $`u`$ 必须在 $`v`$ 之前）。
* 转移条件：在尝试将设备 $`v`$ 加入当前集合 $`S`$ 时，必须保证 $`S`$ 包含了 $`\text{req}[v]`$ 的所有设备，即满足 `(S & req[v]) == req[v]`。
#### 状态转移
1. **基本初始化**：
* 对单点集合，$`\text{dp}[1 \ll i][i] = 0`$，$`\text{cnt}[1 \ll i][i] = 1`$（前提是设备 $`i`$ 没有任何必须在其之前访问的前置依赖，即 $`\text{req}[i] == 0`$）。
* 其他状态初始化为无穷大 / 0。

1. **状态转移方程**：
枚举当前集合 $`S`$ 和当前结尾结点 $`u`$（满足 $`u \in S`$）：
尝试扩展到下一个结点 $`v`$（满足 $`v \notin S`$ 且 `(S & req[v]) == req[v]` 且 $`c_{u,v} \neq -1`$）：
* 新的状态为 $`S' = S \mid (1 \ll v)`$，费用增量为 $`w = c_{u, v}`$。
* 新的潜在费用为 $`\text{new\_cost} = \text{dp}[S][u] + w`$。
* **转移规则**：
* 若 $`\text{new\_cost} < \text{dp}[S'][v]`$：更新最小费用 $`\text{dp}[S'][v] = \text{new\_cost}`$，并重置方案数 $`\text{cnt}[S'][v] = \text{cnt}[S][u]`$。
* 若 $`\text{new\_cost} == \text{dp}[S'][v]`$：累加方案数 $`\text{cnt}[S'][v] = (\text{cnt}[S'][v] + \text{cnt}[S][u]) \bmod 998244353`$。

---

### 3. 统计最终答案

遍历完成后，最终的状态一定是集合 $`S = (1 \ll n) - 1`$（包含所有 $`n`$ 个设备）：

1. 找出所有结尾 $`i`$ 中 $`\text{dp}[(1 \ll n) - 1][i]`$ 的最小值 $`\text{min\_cost}`$。
2. 若 $`\text{min\_cost}`$ 为无穷大，说明无解，输出 `-1 0`。
3. 否则，将所有满足 $`\text{dp}[(1 \ll n) - 1][i] == \text{min\_cost}`$ 的 $`\text{cnt}[(1 \ll n) - 1][i]`$ 累加，即为最优顺序数。

### 4. 完整标准 C++ 代码实现

以下代码遵循了高效率、结构清晰的编码风格，使用静态数组避免动态分配内存。

```cpp
#include <iostream>
#include <algorithm>

using namespace std;

const int MAXN = 18;
const int MOD = 998244353;
const long long INF = 1e18;

int n, m;
long long cost[MAXN][MAXN];
int req[MAXN]; // req[i] 表示访问设备 i 前必须已访问的结点集合掩码

long long dp[1 << MAXN][MAXN];
long long cnt[1 << MAXN][MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    if (!(cin >> n >> m)) return 0;

    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            cin >> cost[i][j];
        }
    }

    // 读入先后约束 (u, v)，注意题目给出的设备通常从 1~n 编集，需转为 0~n-1
    for (int i = 0; i < m; ++i) {
        int u, v;
        cin >> u >> v;
        --u; --v;
        req[v] |= (1 << u);
    }

    int full_mask = (1 << n) - 1;

    // 初始化 DP 数组
    for (int mask = 0; mask <= full_mask; ++mask) {
        for (int i = 0; i < n; ++i) {
            dp[mask][i] = INF;
            cnt[mask][i] = 0;
        }
    }

    // 初始化起点：单元素集合且满足前置约束为 0
    for (int i = 0; i < n; ++i) {
        if (req[i] == 0) {
            dp[1 << i][i] = 0;
            cnt[1 << i][i] = 1;
        }
    }

    // 按掩码从小到大转移
    for (int mask = 1; mask <= full_mask; ++mask) {
        for (int u = 0; u < n; ++u) {
            if (!(mask & (1 << u))) continue;
            if (dp[mask][u] == INF) continue;

            for (int v = 0; v < n; ++v) {
                // v 已经在集合中，跳过
                if (mask & (1 << v)) continue;
                // 不存在直接边，跳过
                if (cost[u][v] == -1) continue;
                // 不满足 v 的前置约束，跳过
                if ((mask & req[v]) != req[v]) continue;

                int next_mask = mask | (1 << v);
                long long next_cost = dp[mask][u] + cost[u][v];

                if (next_cost < dp[next_mask][v]) {
                    dp[next_mask][v] = next_cost;
                    cnt[next_mask][v] = cnt[mask][u];
                } else if (next_cost == dp[next_mask][v]) {
                    cnt[next_mask][v] = (cnt[next_mask][v] + cnt[mask][u]) % MOD;
                }
            }
        }
    }

    // 统计最终答案
    long long min_total_cost = INF;
    long long total_ways = 0;

    for (int i = 0; i < n; ++i) {
        if (dp[full_mask][i] < min_total_cost) {
            min_total_cost = dp[full_mask][i];
            total_ways = cnt[full_mask][i];
        } else if (dp[full_mask][i] == min_total_cost && min_total_cost != INF) {
            total_ways = (total_ways + cnt[full_mask][i]) % MOD;
        }
    }

    if (min_total_cost == INF) {
        cout << "-1 0\n";
    } else {
        cout << min_total_cost << " " << total_ways << "\n";
    }

    return 0;
}

```

## 5. 复杂度与时空分析

* **时间复杂度**：
状态数量为 $`O(n \cdot 2^n)`$，每个状态需要枚举下一个可转移的结点 $`v`$（大小为 $`O(n)`$）。
因此总时间复杂度为 $`\mathcal{O}(n^2 \cdot 2^n)`$。
当 $`n = 18`$ 时，$`18^2 \times 262144 \approx 8.5 \times 10^7`$ 次计算，在 $`2.0`$ 秒的时间限制内可以通过得很轻松。
* **空间复杂度**：
状态空间为 $`O(n \cdot 2^n)`$，使用静态数组保存 $`\text{dp}`$ 与 $`\text{cnt}`$：
$`2^{18} \times 18 \times 8 \text{ B} \approx 37.7 \text{ MB}`$，完全符合 512 MiB 的限制。
